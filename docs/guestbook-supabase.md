# 留言板改成「公开可见」的操作手册（Supabase 免费层）

改之前：留言存在浏览器自己的 localStorage 里，只有你自己那台电脑看得到。
改之后：留言存在 Supabase 的免费数据库里，**点开链接的人都能看到、都能发**，
昵称仍然可以留空（留空显示「匿名」），不需要注册、不需要登录。

配置只要两个值：`SUPABASE_URL` 和 `SUPABASE_ANON_KEY`，填进 `js/pages.js` 顶部。
没填时留言板退回本机模式；填了但连不上时（断网、库被暂停）只提示「暂时连不上留言库」，
不会偷偷退回本机存储 —— 免得你以为发出去了、其实只存在自己电脑上。
两种情况都不报错、也不影响离线打开。

---

## 一、建库（大约 5 分钟）

1. 打开 https://supabase.com ，用邮箱注册（免费，不需要信用卡），
   然后 **New project**。名字随便（例如 `personal-homepage`），
   区域选离你近的（例如 `Southeast Asia (Singapore)`），数据库密码随便生成一个记下来（这里用不到）。
2. 等 1~2 分钟项目创建完成。
3. 左侧点 **SQL Editor** → **New query**，把下面整段粘进去，点 **Run**。

```sql
-- 留言表
create table if not exists public.messages (
  id         bigint generated by default as identity primary key,
  created_at timestamptz not null default now(),
  name       text not null default '',
  body       text not null,
  constraint messages_name_len check (char_length(name) <= 16),
  constraint messages_body_len check (char_length(body) between 1 and 200)
);

-- 按时间倒序取最近几条，加个索引
create index if not exists messages_created_at_idx on public.messages (created_at desc);

-- 开门：行级安全必须打开，规则只放「读」和「写」，不放改和删
alter table public.messages enable row level security;

drop policy if exists messages_read on public.messages;
create policy messages_read on public.messages
  for select using (true);

drop policy if exists messages_insert on public.messages;
create policy messages_insert on public.messages
  for insert with check (
    char_length(name) <= 16
    and char_length(body) between 1 and 200
  );

-- 不建 update / delete 规则，所以前端谁也改不了、删不掉别人的留言
```

4. 左侧 **Settings → API**，记下两个值：
   - **Project URL**，形如 `https://abcdefgh.supabase.co`。
     ref 是十来个字符的小写字母数字，**很容易抄错一个字符**；
     抄错的表现就是页面一直说「暂时连不上留言库」，见第四节末尾的排查办法。
   - **公开的那把 key**：新版控制台叫 **Publishable key**（`sb_publishable_` 开头），
     老版控制台叫 **anon / public**（`eyJ` 开头）。两种都能用，控制台给你哪个就用哪个。

   > 只复制公开的那把 key。旁边那把 **secret key / service_role** 能绕过所有规则、
   > 能删库，**绝对不要**写进前端，永远不要。

5. 把两个值填进 `js/pages.js`：

```js
var SUPABASE_URL = "https://abcdefgh.supabase.co";
var SUPABASE_ANON_KEY = "sb_publishable_...";  // 老控制台里是 eyJ 开头的那一串 anon key
```

   公开 key 本来就是设计成公开的（它会被打包进网页，任何人都能在源码里看到），
   安全靠上面那几条 RLS 规则兜着，所以放进仓库、推上 GitHub Pages 都没问题。

6. 打开网页的「留言」页，发一条，再用**无痕窗口**打开同一个网址，
   能看到刚才那条就说明接通了。

## 二、日常维护

**删留言**（你说的「我随时删」）有两种方式：

- 网页操作：Supabase 左侧 **Table Editor → messages**，鼠标移到那一行，点右边的删除图标。
- SQL 操作：**SQL Editor** 里执行
  ```sql
  delete from public.messages where id = 12;          -- 删某一条
  delete from public.messages where body ilike '%广告%'; -- 批量删
  ```

**看有没有人被拦住**：被 RLS 挡下的请求不会写库。如果有人说「发不出去」，
先看是不是超了长度（昵称 16 字、正文 200 字，超了会被规则拒绝）。

## 三、几个要知道的坑

- **免费项目 7 天没人访问会被暂停**。你这个站是给人看的，只要有人点开就不会暂停；
  真被暂停了，登录 Supabase 在项目页点 **Restore** 即可，数据不会丢。
- **别关 RLS**。如果哪天你为了排查问题执行了 `alter table public.messages disable row level security;`，
  记得立刻开回来，否则任何人都能清空你的表。
- **匿名 + 公开 = 早晚有人来刷广告**。现在只有长度限制和「改不了、删不掉」两条护栏，
  真被刷了再按需加一道（改完点 Run 即可）：
  ```sql
  -- 方案 A：正文里不许出现网址（最常见的广告形态）
  alter table public.messages drop constraint if exists messages_no_link;
  alter table public.messages add constraint messages_no_link
    check (body !~* 'https?://|www\.');
  ```
  更彻底的做法是把「写入」包一层 Cloudflare Worker 加人机验证（Turnstile，免费），
  需要的时候再说。
- **前端只能限长、限不了频率**。所以有人写脚本连点的话，你只能靠后台删。
  真要治本就走上面那条 Worker 方案。

## 四、这条路的边界

- 数据在 Supabase 的服务器上（新加坡等区域），国内一般能直接访问，偶尔会慢。
- 断网、或库被暂停时，留言板会显示「暂时连不上留言库」，**你原来的离线预览不受影响**。
- 这条路径不收集邮箱、不要求登录，与「可匿名」的设计一致；
  IP 不落库，也就没有按 IP 限流的能力（原因见上）。

**排查：页面一直说「暂时连不上留言库」怎么办？**

先在命令行里查一下你的项目域名（把 ref 换成你自己的）：

```
nslookup zsrymnmccnxcymtiysap.supabase.co
```

- 回 **NXDOMAIN**（域名不存在）→ 多半是 `SUPABASE_URL` 里的 ref **抄错了一个字符**。
  ref 是十来位小写字母数字，肉眼很容易串位。去 Settings → API 重新复制 Project URL 对一遍，改完刷新页面。
- 能解析出 IP、但页面还是连不上 → 看 `SUPABASE_ANON_KEY` 是不是复制全了（少一位就是 401）。
- 两样都对还不行 → 去 SQL Editor 确认 `messages` 表和那几条 RLS 规则都还在。
