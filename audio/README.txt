音乐放这里
==========

一句话版本
----------
把 mp3 放进这个 audio/ 文件夹 → 在项目根目录跑 `node tools/scan-audio.js`
→ 连同 mp3 一起提交、推送。之后**所有打开网站的人**都能在首页音乐卡和
「歌库」页里听到这些歌。

完整的加歌步骤
--------------
1) 把音频文件拷进 `personal-homepage/audio/` 目录里。

   文件名写成「歌手 - 歌名.mp3」，例如：
       郭静 - 爱情讯息.mp3
       陈奕迅 - 十面埋伏.mp3

   扫描脚本会按这个格式自动拆出歌手和歌名；如果文件里本来就有
   artist / title 标签，优先用标签里的。

2) 在 `personal-homepage` 目录下跑：

       node tools/scan-audio.js

   它会重新生成 `audio/library.js`（歌库清单），并在屏幕上列出识别到的曲目。
   只想先看看结果、不写文件的话，加 `--dry`：

       node tools/scan-audio.js --dry

   如果提示找不到 ffprobe：装上 ffmpeg，或者把 FFPROBE 环境变量指向
   ffprobe 可执行文件（本机已经在 C:\Users\13502\.deepworks\tools\ffprobe.exe）。

3) 提交并推送，让音频和清单一起上线：

       git add audio/
       git commit -m "歌库：加了几首歌"
       git push

   部署完成后刷新线上页面，曲子就在「歌库」页里了，首页那张音乐卡
   也会直接拿这份清单当播放列表。

为什么必须提交文件，而不是在页面上拖进去
----------------------------------------
把 mp3 拖进浏览器时，页面只是给这个本地文件生成一个临时地址
（blob: 开头），它只存在于**你自己这台电脑的这次会话**里：
关掉页面就没了，也永远不会离开你的电脑。所以拖拽只适合自己试听，
想让别人听到，音频文件必须作为网站的一部分被发布出去。

注意事项
--------
- 版权：请只放自己有权利公开分享的音频。把商业歌曲的完整音频传到公开
  网站上属于侵权风险，课程作业也建议用无版权音乐或自己录的素材。
- 体积：音频文件很占空间。GitHub Pages 建议仓库控制在 1GB 以内、
  月流量 100GB 以内。几首歌没问题，几百首就要换对象存储或音频托管了。
- 体积优化：如果文件太大，可以先转成 128~192 kbps 的 mp3，人耳几乎听不出
  差别，体积能小一半以上。
- 格式：mp3 最稳。浏览器解不了 wma，扫描脚本会提醒你转格式。
  支持 mp3 / m4a / aac / ogg / opus / wav / flac / wma（wma 不建议）。
- 页面不会自动播放（浏览器的自动播放策略会拦），要手动点一下播放键。
- 首页那张卡支持单曲循环、上一首 / 下一首、音量、点进度条跳转。

其他文件
--------
`library.js` 是扫描脚本生成的歌库清单，不用手改；手改的话注意别写坏语法，
语法一坏整页音乐模块都起不来。
