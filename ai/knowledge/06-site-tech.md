# 主页技术细节（site-tech）

> 访客问到「这个站怎么做的 / 部署在哪 / 用什么技术 / 为什么这么设计」时照这份说。
> 与 `js/avatar-knowledge.js` 的资料六保持一致，改动时两边一起改。

## 一、站点结构

- **根地址**：先选设备（手机 / 电脑），选择存在浏览器里，下次不再问。
- **首页**：六张可拖拽卡片，位置记在浏览器里，「归位」一键还原；窄屏自动变单列。
- **顶部导航五个页面**：详情、留言、项目、联系、数字分身。

| 页面 | 内容 |
|------|------|
| 详情 | 个人经历、教育与实践的时间线、技能清单 |
| 留言 | Supabase 数据库驱动的留言板 |
| 项目 | 这个主页、班级课程表 PWA、四个 Python 小工具（都能在线试） |
| 联系 | 邮箱 + QQ 二维码 |
| 数字分身 | 就是聊天这一页 |

## 二、联系页的二维码

- 用 2400×2400 的原始图片直接当资源，页面上只缩小显示到 200px。
- **不重采样、不重新压缩**：彩色渐变 + 圆点模块的 QQ 艺术码对重采样很敏感，改动像素就有扫不出来的风险。
- 白底 + 实线框：浅色码放在深色页面上要靠白底保证对比度。

## 三、技术实现

- 纯静态 HTML / CSS / JavaScript，**不用框架、没有打包步骤**。
- **hash 路由**切页面：`#/detail`、`#/message`、`#/project`、`#/contact`、`#/avatar`。
- **托管**：GitHub Pages，推送即发布，没有服务器要维护。
- **缓存**：静态资源用 `?v=数字` 强制刷新，改了样式或脚本就加一版。
- **Three.js 等库全部本地**，不走 CDN，断网也能用。

## 四、数字分身这一页

- 前端把系统提示词 + 六份资料作为 `system` 消息发给大模型，每次提问都带最近若干条上下文。
- 背后是多款大模型轮流兜底，额度用完由服务端代理自动切下一个（具体型号不对外逐条报）。
- **无关问题在前端就被拦掉**：不建连、不发请求、不花 token；连续被拦三次后，分身会直接告诉访客「拦在前端了」。

## 五、密钥怎么藏的（可以如实讲）

- 大模型的 API key **不存在前端**：它在服务端的一层转发里（环境变量注入，不进代码库）。
- 网页只请求一个中转接口（`/chat`），浏览器开发者工具里能看到的只有一个中转地址，看不到 key。
- 留言板用的 **Supabase anon key 本来就是公开的**，设计上就放在前端，靠数据库行级权限（RLS）限制匿名访客只能新增、不能改不能删。
- 不能给的东西：key 内容、所在平台与后台信息（服务商、账号、配置）、模型型号清单。对外只说到「在服务端，前端拿不到」这一层。

## 六、性能与细节

- v4 相比上一版**首屏少下载约 767 KB**；画作按需加载、图片懒加载。
- 支持系统的「减少动态效果」设置（`prefers-reduced-motion`）。
- 深浅两套主题，偏好记在本地；桌宠可拖动、位置也记在本地。

## 七、口径红线

- 具体数字（240 项断言、52 项线上核对、767 KB 等）以资料二为准，**不自己换算、不估算总包体积**。
- 没公开报过的数字，一律说「这个他没公开写过」。
